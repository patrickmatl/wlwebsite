# DNS for wlcreationx.co.za

A verbatim capture of the live zone, taken before any hosting migration.

**If email ever stops working after a DNS change, this file is how you put it
back.** The four email records below are the ones that matter: recreate them
exactly, character for character, at whatever host the domain ends up on.

Captured 2026-08-26 from live public DNS. Authoritative nameservers at the time
were `ns1.vercel-dns.com` / `ns2.vercel-dns.com`.

## Why each one matters

| Record | Breaks if lost |
|---|---|
| `MX` ×2 | You stop receiving email entirely |
| `A mail` | The MX target stops resolving, so inbound mail bounces |
| `TXT` SPF | Outgoing mail fails SPF and lands in spam |
| `TXT _dmarc` | DMARC alignment breaks; reputation degrades |
| `TXT default._domainkey` | DKIM signatures stop verifying. This is a **public** key, safe to store here, but it must match the private key cPanel signs with — it cannot be regenerated by hand |
| `TXT` google-site-verification | Search Console de-verifies the property |

## Known issues to fix while you are in here

Two faults were found in this zone and are **not** corrected above, because the
capture is deliberately verbatim:

1. **SPF names the wrong server.** It lists `ip4:198.251.89.34`, but mail
   actually leaves from `198.251.89.161`. It only passes today by accident, via
   the `mx` mechanism. It also has an `a` mechanism, which authorises the
   website's IPs — Vercel's shared edge — to send as this domain.
   Corrected: `v=spf1 mx ip4:198.251.89.161 ip4:198.251.89.34 include:sendersrv.com include:spf.mailjet.com ~all`

2. **DMARC reports go nowhere.** `rua=mailto:admin@wlcreationx.co.za` — that
   mailbox does not exist, so every aggregate report bounces and you have no
   visibility into delivery failures. Either create the mailbox or repoint it.
